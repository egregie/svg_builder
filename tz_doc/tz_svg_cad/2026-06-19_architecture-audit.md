## Резюме `(G)`
Корень будущих проблем — не отдельные баги, а **отсутствие контракта артефакта на выходе `compile_svg.py`**. Из этого пробела вытекают все три блокера: SKETCH-гейт (`261ca96`) смешивает визуальное качество с топологической пригодностью; R-03 разрушает геометрию без инварианта; ND-04 фиксирует, что схемы выхода вообще нет. Решение — ввести **контракт выходного SVG как единый источник истины (ND-04 — keystone)**; фиксы SKETCH-гейта и R-03 становятся пунктами этого контракта, а не точечными патчами. Это устраняет класс проблем целиком, а не один экземпляр.

## Логические и архитектурные ошибки `(G)`

### E-1. Гейт релиза смешивает разные оси качества (`261ca96`)
- **Симптом** `(S)`: понижение `sketch SSIM release gate 0.90 → 0.75`.
- **Корень** `(G)`: SSIM измеряет визуальное сходство с растром; он **не** измеряет замкнутость контуров и manifold-пригодность. Один скалярный гейт решает «релизить ли», объединяя несовместимые критерии.
- **Следствие** `(G)`: SKETCH-вывод проходит SSIM 0.75, но остаётся non-manifold → попадает в корпус → ломает будущий `compile_3mf.py`. Часть из 66 объектов потенциально непригодна.

### E-2. Деструктивная фильтрация без инварианта (R-03)
- **Симптом** `(S)`: при малом числе foreground-paths фильтр (`extract_layer_shapes`/`get_closest_color_token`) выбрасывает слишком много путей.
- **Корень** `(G)`: фильтр — необратимый `discard` по абсолютному порогу цветового расстояния, без нижнего инварианта («слой переднего плана сохраняет ≥1 путь») и без маршрута отказа.
- **Следствие** `(G)`: тихий пустой/неполный SVG проходит дальше как «успех». 3MF из него → пустой меш.

### E-3. Нет контракта выходного артефакта (ND-04)
- **Симптом** `(S)`: формат вывода SVG не определён (inline/standalone/sprite).
- **Корень** `(G)`: канонический артефакт пайплайна не имеет схемы: не зафиксированы единицы, нормализация `viewBox`, обязательные метаданные, ограничения на пути. Потребители (3MF, внешние тулзы) не имеют стабильного входа.
- **Следствие** `(G)`: каждый downstream-модуль вынужден угадывать структуру → хрупкость, дублирование парсинга, R-06 (px→мм не определён).

### E-4. Нет единого источника истины для конфигурации/версии (governance)
- **Симптом** `(S)`: `TZ_v2.9` (`current_state.md`) vs `TZ_v3.1` (архив); StarVector `8B INT4` vs `1B` (`walkthrough.md`); активная ветка `feat/classifier-tonal-routing` (`HANDOFF`) vs релиз `261ca96`/`master` (`current_state`).
- **Корень** `(G)`: версия спецификации, движок, пороги гейтов и токены дублируются в прозе разных файлов вместо одного машиночитаемого конфига в `00_governance/`.
- **Следствие** `(G)`: невозможно детерминированно сказать, какие правила действуют. Любой фикс рискует опираться на устаревшее значение.

### E-5. Две конкурирующие цветовые модели
- **Симптом** `(S)`: мультитокенная фильтрация (`--dark/--white/--bg/--bg-alt`, `walkthrough.md`) vs `validate_monochrome` (монохром-стандарт `TZ_v3.1`, архив).
- **Корень** `(G)`: сосуществуют два режима интерпретации цвета без явного арбитра. Для 3MF нужен один fill; для мультитокена — палитра.
- **Следствие** `(G)`: фильтр E-2 ведёт себя по-разному в зависимости от того, какая модель «в силе», что и усиливает R-03.

### E-6. Provenance не отслеживается (R-01 fallback)
- **Симптом** `(S)`: StarVector→VTracer fallback при отсутствии `fairscale`.
- **Корень** `(G)`: артефакт не записывает, каким движком произведён и был ли fallback. Геометрия StarVector (SKETCH-склонная) и VTracer (другая топология, иной anchor-профиль) неразличимы downstream.
- **Следствие** `(G)`: невозможно отфильтровать 3MF-пригодные по происхождению; отладка качества вслепую.

### E-7. Версионирование паспортов не определено (ND-06)
- **Симптом** `(S)`: ND-06 открыт — политика версионирования паспортов при повторной деконструкции отсутствует.
- **Корень/следствие** `(G)`: повторный `deconstruct.py` может перезаписать/задублировать `COMP-*` недетерминированно → дрейф графа знаний. Не блокер 3MF, но архитектурный долг.

## Целевая архитектура — принципы `(G)`

1. **Контракт-ориентированный пайплайн.** Каждая стадия эмитит версионированный артефакт, валидируемый по схеме. Канонический выход `compile_svg.py` = `standalone` SVG со схемой (ND-04 keystone).
2. **Разделение осей качества.** Визуальная (SSIM), топологическая (замкнутость/manifold), цветовая (монохром/токен-конформность) — независимые гейты. Потребитель объявляет требуемые оси. `3mf_eligible` выводится из топологической+цветовой осей, не из SSIM.
3. **`render_mode` — атрибут первого класса.** Пропагируется в метаданные артефакта и управляет downstream-пригодностью. `SKETCH_VECTOR` → `3mf_eligible = false` независимо от SSIM.
4. **Инварианты на деструктивных операциях.** Фильтрация не может опустошить слой переднего плана: нарушение → `quarantine` с диагностикой, не тихий пустой выход.
5. **SSOT конфигурации в `00_governance/`.** Один машиночитаемый файл: версия ТЗ, движок, пороги гейтов, цветовая модель, токены. Документы состояния ссылаются на него, не дублируют.
6. **Provenance в каждом артефакте.** Движок, флаг fallback, параметры, базовый коммит, результаты гейтов.
7. **Идемпотентные/версионированные паспорта** при повторной деконструкции (ND-06).

## Риски миграции `(G)`
- **Перекомпиляция корпуса.** После ввода контракта 66 объектов нужно ре-валидировать; часть уйдёт в `quarantine`. Это ожидаемо, не регрессия.
- **Откат 0.75 — антипаттерн.** Понижение гейта сделано намеренно для SKETCH; откат сломает легитимный 2D-кейс. Фикс — ортогональная ось, не возврат значения.
- **Дрейф версий не разрешён.** Все T-задачи зависят от подтверждённой действующей версии ТЗ (T0). Без T0 фиксы могут опираться на устаревшие пороги.

## Альтернативы `(G)`
- **A. Точечные патчи без контракта.** Быстро, но E-3 остаётся → каждый новый потребитель повторит проблему. Отклонено.
- **B. Контракт-keystone (рекомендуется).** ND-04 первым, остальные фиксы — его пункты. Выше стоимость T0/T1, ниже совокупная стоимость владения.
- **C. Полный рефактор governance + SSOT сразу для всего проекта.** Максимально «правильно», но раздувает область за пределы трёх блокеров и Stage-3-заморозки. Отложено до закрытия блокеров.
