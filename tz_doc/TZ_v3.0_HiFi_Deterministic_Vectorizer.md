# ТЕХНИЧЕСКОЕ ЗАДАНИЕ v3.0: HIFI DETERMINISTIC VECTORIZER

**Версия:** 3.0 (задача: высокая точность отрисовки SVG без нейросетевого инференса в критическом пути)
**Статус v2.8:** StarVector 8B INT4 активирован технически, но качество выхода неприемлемо (см. раздел 1).
**Принцип:** Бесплатно, локально, детерминированно, с измеримым контролем качества.

---

## 1. Анализ корневых причин низкого качества `[ФАКТ]`

### D-01: Галлюцинации StarVector (критический дефект)
`05_output_svg/COMP-001.svg` содержит `<text>` с символом «Θ» и шрифтом «ZillaSlab»,
отсутствующими во входном изображении. Причины, неустранимые на данном железе:
- Image-to-SVG модель сжимает вход до 224×224 — текст и мелкая геометрия теряются до инференса.
- Модель обучена на иконках/эмблемах и при выходе за распределение «вспоминает»
  похожие образцы из обучения вместо воспроизведения входа.
- INT4-квантование дополнительно деградирует точность.
**Вывод:** StarVector исключается из критического пути. Любая модель im2svg,
влезающая в 8 ГБ VRAM, не обеспечит воспроизведение произвольного логотипа.

### D-02: Лимит опорных точек уничтожает детализацию
`vtracer_bridge.py` суммирует точки **всех** путей слоя и итеративно повышает
`length_threshold`, пока сумма ≤ `anchor_points_limit` (45). Логотип с круговым
текстом требует тысяч точек. Правило атомарности в текущей реализации — главный
разрушитель качества алгоритмической ветки.

### D-03: Цветовая фильтрация отбрасывает легитимную геометрию
`extract_layer_shapes` оставляет только пути, чей ближайший токен совпадает с
`color_token` слоя. Паспорт описывает ровно 2 слоя на любой объект — всё, что не
попало в эти 2 цвета, теряется.

### D-04: QA-гейт не измеряет визуальную точность
Аудит A05 проверяет XML-валидность и запрещённые цвета. Метрики сходства с
исходником нет — поэтому пустые и галлюцинированные SVG получают статус Success.

## 2. Архитектурное решение `[РЕШЕНИЕ]`

**Новый движок `ops/scripts/hifi_vectorize.py` (агент A06 «hifi-vectorize»):**
детерминированная реконструкция с перцептивным контуром обратной связи.

```
PNG → препроцессинг → квантование цветов (K-means, Lab) → K бинарных масок
    → VTracer (binary) по каждой маске → сборка composite SVG (слои по площади)
    → растеризация (resvg) → SSIM против эталона → автоподбор параметров VTracer
    → лучший кандидат → QA-гейт A05 (XML + forbidden colors) → релиз
```

### 2.1 Препроцессинг
- Альфа-канал флэттенится на белый фон (PIL).
- Изображения с max(w,h) < 600 px апскейлятся ×2 (bicubic) для качества трассировки;
  итоговый viewBox остаётся в исходных координатах.

### 2.2 Квантование цветов
- K-means в CIE Lab (OpenCV), K подбирается автоматически: минимальное K ∈ [2..6],
  при котором средняя ошибка квантования ΔE < порога (по умолчанию 6.0).
- Фон = кластер, доминирующий в 1-пиксельной рамке изображения.

### 2.3 Послойная трассировка
- Для каждого не-фонового кластера строится бинарная маска (чёрное на белом),
  трассируется VTracer в режиме `colormode='binary'`, `mode='spline'`.
- Никаких лимитов суммарных опорных точек. `filter_speckle` отвечает за чистку шума.
- Слои сортируются по площади (большие ниже), фон — `<rect>`.

### 2.4 Политика цветов (совместимость с Zero Black Policy)
- Кластер маппится на базовый токен из `design-tokens.json`, если RGB-расстояние ≤ 24;
  чистый чёрный/белый всегда маппится на `--dark`/`--white` (Zero Black Policy).
- Иначе создаётся вспомогательный токен `--aux-N: #hex` **внутри `<style>`** —
  это сохраняет точность цвета и проходит QA (hex вне `<style>` по-прежнему запрещён).

### 2.5 Перцептивный QA-цикл (ключевое новшество)
- **Эталон:** квантованное изображение, где цвет каждого кластера заменён на
  финальный выходной цвет (токен/aux) — идеальный результат компиляции.
- **Кандидат:** SVG растеризуется `resvg-py` (CSS `var()` предварительно
  подставляется hex-значениями, т.к. resvg не поддерживает переменные).
- **Метрика:** SSIM (scikit-image, по каналам) + доля совпавших пикселей.
- **Автоподбор:** сетка параметров VTracer (`filter_speckle` × `corner_threshold` ×
  `length_threshold`), ранний выход при SSIM ≥ 0.985. Выбирается лучший кандидат.
- **Гейт:** SSIM ≥ 0.93 — релиз; ниже — quarantine + запись в `ops/logs/qa_failures.jsonl`.
- Дополнительно логируется SSIM против оригинального (неквантованного) растра — справочно.

### 2.6 Интеграция в экосистему агентов
- `compile_svg.py` (A05): по умолчанию использует HiFi-движок для всего объекта
  (движок сам определяет фактическое число слоёв; декларация 2 слоёв в паспорте —
  метаданные, не ограничение). Легаси-путь (VTracer-bridge/StarVector) сохраняется
  под флагом `--legacy`.
- `vtracer_bridge.py`, `starvector_inference.py`, `deconstruct.py`, паспорта и схема —
  не изменяются (обратная совместимость, откат через флаг).
- Журналы: `agent_trace.jsonl` (agent_id=A06), метрики SSIM в каждой записи.

Прогон `ops/scripts/preflight.py` (dry-run, без записи в граф) на 13 новых картинках

\* SSIM(orig) занижен из-за полупрозрачного фона PNG; силуэт воспроизведён точно.

Найден и устранён критический дефект:

**D-05: VTracer Rust-overflow на плотных изображениях `[ФАКТ, ИСПРАВЛЕН]`**
`kover_05.jpg` (детальный персидский ковёр, 1.69 МП) вызывал
`pyo3_runtime.PanicException: overflow` в `visioncortex-0.8.10/clusters.rs:323`
и **аварийно завершал весь процесс**. Дефект зависит от плотности, не от размера
(portal_13 @ 2.07 МП работает). `filter_speckle` не помогает — overflow происходит
в кластеризации до фильтрации спеклов. Решение в `hifi_vectorize.py`:
- `trace_mask` ловит панику (`BaseException`) и поднимает `TraceOverflowError`;
- `trace_all_layers` реактивно понижает разрешение трассировки ×0.7 (label-map,
  NEAREST) до floor `MIN_TRACE_MP=0.4` МП, пока все слои не протрассируются;
- ниже floor — best-effort с пропуском неподдающихся слоёв (без краха).
Порог проверен эмпирически: ковёр перестаёт переполняться на ~0.42 МП.

Выводы по классам:
- Перцептивный гейт работает как задумано: все 4 непригодных объекта (фото,
  текстуры, тяжёлый градиент) получают FAIL → карантин, а не ложный «успех».
- Рекуррентное слабое место — крупные плавные **градиенты** постеризуются в пятна/
  полосы (фоны bambi, ava, portal_12/13). Ограничение flat-векторизации (КО-2).
- На **фото** token-snapping даёт цветовой сдвиг (серая стена → `--herbal`). Фото —
  не целевой класс пайплайна (КО-3).
- Изображения ~2 МП без даунскейла трассируются медленно (~50 с, portal_13).

## 6. Перспектива (вне объёма v3.0)

- Распознавание текста (OCR) и замена трассированных букв на `<text>` с подбором
  шрифта — только при появлении требования редактируемости текста; для точности
  отрисовки трассировка предпочтительнее.
- Фиттинг примитивов (круги/прямоугольники вместо path) — оптимизация размера файла.
- StarVector остаётся опциональным экспериментальным движком вне релизного пути.
