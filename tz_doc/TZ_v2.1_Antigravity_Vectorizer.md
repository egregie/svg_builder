## 1. Резюме и стратегическое решение `[ВХОД]`

Проект проектируется не как утилитарный скрипт-конвертер, а как **Presentation Intelligence Platform / Экспертная экосистема инструментов** в агентной среде разработки. Основная цель системы: один раз деконструировать растровый объект, очистить его параметры, сформировать его текстовое описание и многократно использовать для гарантированно точной векторной реконструкции.

Стратегические архитектурные принципы:

- **Парадигма Foundation-First:** Любая прямая работа над генерацией кода SVG или вызовом рендер-движков полностью заморожена до проектирования жестких схем данных и онтологии системы.
- **Промежуточный декларативный слой:** Обязательный промежуточный шаг — создание **Технического паспорта объекта (`.md`)**. Паспорт — формат-агностичная контентная матрица. Содержит сухие семантические и геометрические данные, полностью изолированные от финального стиля и движка сборки.
- **Первый артефакт системы:** Файл `00_governance/ontology_v1.json`. До момента его компиляции и фиксации структуры запуск любых агентов строго запрещен.

## 2. Верифицированная фактбаза компонентов `[ВХОД]`

### 2.1 Окружение Google Antigravity

- Агентный IDE, в котором локальные агенты планируют, пишут и исполняют код в терминале и редакторе, возвращая детерминированные артефакты.
- Полная поддержка стандарта **Agent Skills** (конфигурация строго через файлы `SKILL.md`) и протоколов MCP.
- Автоматизация установки и обнаружения расширений через Skills CLI с помощью утилиты `find-skills`.

### 2.2 Модули обработки `[ВХОД]`

1. **VTracer** — алгоритмический движок. Лицензия MIT. Локальная работа через CLI/Python-биндинги (`pip install vtracer`). Без внешних зависимостей и ключей.
2. **StarVector** — нейросетевой движок (модели **1B** и **8B**). Лицензия Apache 2.0. Оффлайн-инференс через библиотеку Transformers на локальном GPU/CPU. Генерирует SVG-код текстовыми токенами.
3. **Локальный контур безопасности:** Облачные редакторы и внешние генераторы полностью исключены из пайплайна.

## 1. МЕТАДАННЫЕ ИСХОДНИКА
- **Файл:** source_logo.png
- **Разрешение:** 1024x1024 px

- **Провенанс:** Локальный диск / Клиентский ассет

## 2. СЕМАНТИЧЕСКАЯ ДЕКОНСТРУКЦИЯ (СЛОИ)
*Слои в порядке наложения от заднего плана к переднему.*

### Слой 1: Фоновая подложка
- **Тип геометрии:** Сплошной прямоугольник (Bounding Box)
- **Координаты границ:** [0, 0, 1024, 1024]
- **Выбранный токен цвета:** `--bg-alt`

### Слой 2: Центральный контур
- **Тип геометрии:** Замкнутый составной путь (Compound Path)

## 3. СЛУЖЕБНЫЕ МЕТКИ АВТОМАТИЗАЦИИ
- **Статус деконструкции:** Верифицировано
- **Целевой путь экспорта:** /05_output_svg/res_comp_01.svg
- **Ссылки на граф:** entity_id: logo_primitive_01, source_ref: SRC-0021

## 6. Экосистема локальных агентов `[ВХОД]`

```
[Исходный Растр]
       ↓
  A01: Deconstructor  → (Экстракция параметров в сырой лог)
       ↓
  A02: Validator      → (Проверка дублей и нормализация ID по онтологии)
       ↓
  A03/A04: Engines    → (Параллельная генерация SVG через VTracer/StarVector)
       ↓
  A05: QA Auditor     → (Парсинг XML, проверка Zero Black, экспорт в /05_output_svg/)
```

**A01 — Deconstructor Agent (`raster-deconstruct`)**
Вектор мысли: поиск и деконструкция форм на основе математических и семантических границ. Полное игнорирование шума и артефактов сжатия.
Промпт: «Ты — оптический аналитик системы Antigravity. Разложи входящее растровое изображение на геометрические составляющие. Избегай размытых описаний. Формат: Слой → Тип геометрии → Координаты → Предлагаемый движок. Записывай результаты в 02_processing/».

**A02 — Ontology Guard & Validator (`ontology-normalize`)**
Вектор мысли: критическое мышление, нормализация сущностей, чистка дублирующихся путей.
Промпт: «Ты — хранитель онтологии проекта. Берешь сырые данные из 02_processing/ и проверяешь соответствие схеме ontology_v1.json. Нормализуй сущности: круг / окружность / скругленный полигон → единые канонические ID с алиасами. Сомнительные или накладывающиеся пути удаляй».

**A03 — Vector Compiler (VTracer Bridge) (`vtracer-bridge`)**
Вектор мысли: математическая точность аппроксимации кривых Безье, жесткий контроль параметров CLI.

**A04 — Neural Vectorizer (StarVector Inference) (`starvector-inference`)**
Вектор мысли: семантическое понимание сложных художественных образов, локальный инференс без галлюцинаций. Правило атомарности: длина токена пути не должна вызывать переполнения контекста.
Промпт: «Ты — UX-архитектор векторного кода. Возьми семантическое описание из паспорта и сгенерируй валидный SVG-код для сложных художественных слоев. Только чистые теги путей. Цвет и шрифты — через CSS-переменные дизайн-токенов».

**A05 — SVG QA Auditor (`svg-qa-gate`)**
Вектор мысли: проверка синтаксиса, контроль переполнения папок, валидация дизайн-инвариантов. Ключевой маркер: клинический отказ в выпуске релиза при ошибках рендеринга или незакрытых тегах XML.

## 7. Жесткие правила проектирования (Hard Rules) `[ВХОД]`

1. **Strict Local-First:** Никакие данные изображений или сгенерированный код не передаются на внешние облачные платформы.
2. **Разделение контента и стиля:** Паспорт не содержит жестко зашитых HEX-кодов или названий шрифтов. Все параметры резолвятся из `design-tokens.json`.
3. **Zero Black Policy:** Полный отказ от `#000` / `#000000`. Применяются только реальные токены (`--dark #2C3440`, `--bg #F8F6F4`, `--herbal #6D8470`). Толщина линий — по шкале привязки.
4. **Трассируемость изменений:** Весь граф, индексы и паспорта — под локальным Git. Полный детерминизм и откат к любой итерации.

## 8. Риски, митигации и альтернативы `[ВХОД]`

- **Риск: Синтаксические ошибки в LLM-выводе StarVector.**
  Митигация: A05 пропускает финальный файл через `xml.etree.ElementTree`. При ошибке — сборка блокируется.

- **Риск: Подмена/отсутствие системных шрифтов при рендере SVG текстовых слоев.**
  Митигация: Декларативное встраивание шрифтов в тег `<style>` внутри SVG на этапе компиляции.

- **Альтернатива хранилища графа:** Phase 0–2 — плоские JSON + git-индекс. При масштабировании до тысяч объектов — переход на SQLite/JSONL.

## 13. Спецификация `AGENTS.md` и недостающий промпт A03 `[ДОПОЛНЕНО v2.1]`

Файл: `00_governance/AGENTS.md`

Определяет протокол взаимодействия агентов: порядок передачи артефактов, форматы входных/выходных данных каждого агента, условия блокировки цепочки.

```markdown
# AGENTS.md — Протокол агентной экосистемы

## Общие правила
1. Агент принимает только артефакты с валидным статусом из предыдущего этапа.
2. Запись в следующую папку разрешена только после успешного завершения текущего этапа.
3. При ошибке: запись в ops/logs/, статус задачи → Failed, цепочка блокируется.

## Входы и выходы

| Агент | Вход | Выход | Папка выхода |
|-------|------|-------|--------------|
| A01 | Растр из 01_input_raster/ | Сырой лог деконструкции (JSON) | 02_processing/ |
| A02 | Сырой лог из 02_processing/ | Нормализованный паспорт (JSON) + .md | 03_knowledge_graph/, 04_passports/ |
| A03 | Паспорт слоев Tier_A | SVG-файл (VTracer) | 05_output_svg/staging/ |
| A04 | Паспорт слоев Tier_B | SVG-файл (StarVector) | 05_output_svg/staging/ |
| A05 | SVG из staging/ | Валидированный SVG или Error-репорт | 05_output_svg/ или ops/logs/ |

## Блокирующие условия
- A01 не запускается если ontology_v1.json не зафиксирован в Git.
- A02 не записывает паспорт если не пройдена passport_schema_v1.json.
- A03/A04 не запускаются если статус паспорта ≠ Verified.
- A05 блокирует релиз если SVG содержит: незакрытые теги, forbidden-цвета, невалидный XML.
```

**Недостающий промпт A03** (VTracer Bridge):
«Ты — прецизионный компилятор векторных путей. Получи паспорт объекта из 04_passports/ и извлеки все слои с engine=VTracer. Для каждого слоя сформируй CLI-команду vtracer с параметрами из vtracer_params паспорта. Выполни команду. Проверь, что количество опорных точек в выходном path не превышает anchor_points_limit. При превышении — увеличь length_threshold на 1 и повтори. Запиши результат в 05_output_svg/staging/. Логируй каждую операцию в ops/logs/».

## 14. Алгоритм роутинга Tier A / B / C `[ДОПОЛНЕНО v2.1]`

В ТЗ v2.0 тиры определены, но не специфицирован механизм принятия решения о маршрутизации слоя. Это устраняется ниже.

### Матрица роутинга

Агент A01 или A02 присваивает движок каждому слою по детерминированному набору критериев:

| Критерий | VTracer (Tier A) | StarVector (Tier B) | OpenCV pre-filter (Tier C) |
|----------|-----------------|--------------------|-----------------------------|
| Количество цветов в слое | ≤ 4 | > 4 | любое |
| Наличие градиентов | Нет | Да | N/A |
| Контрастность ребер (Canny score) | > 0.7 | ≤ 0.7 | N/A |
| Тип содержимого | Текст, чертеж, иконка | Иллюстрация, логотип, фото | Зашумленный исходник, JPEG-артефакты |
| SNR изображения | > 30 дБ | > 30 дБ | ≤ 30 дБ |

### Детерминированный алгоритм (псевдокод)

```python
def route_layer(layer: LayerData) -> str:
    if layer.snr_db <= 30:
        return "OpenCV+VTracer" if layer.color_count <= 4 else "OpenCV+StarVector"
    if layer.has_gradient or layer.color_count > 4:
        return "StarVector"
    if layer.canny_score > 0.7 and layer.color_count <= 4:
        return "VTracer"
    # Неопределенный случай — требует ручного решения
    raise RoutingAmbiguityError(f"Layer {layer.id}: insufficient routing signal")
```

`RoutingAmbiguityError` → запись в `ops/logs/routing_conflicts.jsonl`, статус слоя → `Pending Manual Review`.

## 16. Дорожная карта фаз Phase 1–3 `[ДОПОЛНЕНО v2.1]`

В ТЗ v2.0 детализирована только Phase 0. Ниже — структура последующих фаз.

### Phase 0 — Foundation (текущий спринт)

Цель: зафиксировать управляющие артефакты, инициализировать структуру проекта.

1. Инициализировать папки `.agent/skills/`, `00_governance/`, `02_processing/`, `ops/logs/`.
2. Зафиксировать `ontology_v1.json`, `design-tokens.json`, `passport_schema_v1.json`, `AGENTS.md` в Git.
3. Развернуть `find-skills`, проверить доступность VTracer (`pip install vtracer`), зафиксировать версию.
4. Проверить доступность StarVector 1B (минимальные требования: 4 ГБ VRAM или CPU-инференс).
5. **Гейт выхода Phase 0:** все файлы `00_governance/` зафиксированы в Git. `[НЕТ ДАННЫХ]` из раздела 9 закрыты.

### Phase 1 — Ingestion & Deconstruction

Цель: запустить A01 и A02 на первой партии изображений.

1. Заполнить `01_input_raster/high_contrast/` тестовой партией (объем `[НЕТ ДАННЫХ]`).
2. Запустить A01 → A02 на партии.
3. Убедиться, что все паспорта проходят `passport_schema_v1.json`.
4. Зафиксировать индексы в `03_knowledge_graph/`.
5. **Гейт выхода Phase 1:** 100% паспортов имеют статус `Verified`.

### Phase 2 — Reconstruction

Цель: параллельный запуск A03 и A04, генерация SVG в `staging/`.

1. Запустить A03 (VTracer) на всех Tier_A слоях.
2. Запустить A04 (StarVector) на всех Tier_B слоях.
3. Собрать составные SVG из слоев в staging/.
4. **Гейт выхода Phase 2:** все SVG в staging/ синтаксически валидны (A05 pre-check).

### Phase 3 — QA & Release

Цель: финальная валидация и экспорт в `05_output_svg/`.

1. A05 сканирует staging/ на forbidden-цвета, незакрытые теги, незакрытые пути.
2. Прошедшие файлы перемещаются в `05_output_svg/`.
3. Генерируется финальный QA-отчет в `ops/logs/qa_failures.jsonl`.
4. **Гейт выхода Phase 3:** нулевой счетчик в `qa_failures.jsonl`.

## 17. Политика обработки ошибок агентов `[ДОПОЛНЕНО v2.1]`

Исходное ТЗ содержит митигации для двух технических рисков, но не определяет общий протокол поведения агентов при сбоях.

### Матрица действий при ошибках

| Тип ошибки | Агент | Действие | Состояние цепочки |
|-----------|-------|----------|-------------------|
| Невалидный паспорт (schema fail) | A02 | Лог в `validation_errors.jsonl`, статус → `Failed` | Блокировка A03/A04 для данного объекта |
| RoutingAmbiguityError | A01/A02 | Лог в `routing_conflicts.jsonl`, статус → `Pending Manual Review` | Объект пропускается, остальные продолжают |
| VTracer CLI error (exit code ≠ 0) | A03 | Повтор с fallback-параметрами (max 2 попытки), затем лог + блокировка | Объект пропускается |
| StarVector inference timeout / OOM | A04 | Попытка переключения на модель 1B (если была 8B), затем лог + блокировка | Объект пропускается |
| Невалидный XML в SVG | A05 | Лог в `qa_failures.jsonl`, файл → quarantine/, не перемещается в output | Блокировка релиза объекта |
| Forbidden color в SVG | A05 | То же | Блокировка релиза объекта |

**Правило:** ни один агент не молча проглатывает ошибку. Каждый сбой — запись в лог с полным контекстом. Цепочка продолжает работу на остальных объектах, если ошибка изолирована к одному артефакту.

**Добавить в древо папок:**
```text
05_output_svg/
├── staging/     # Временное хранение перед QA
├── quarantine/  # SVG, не прошедшие QA A05
└── (корень)     # Релизные файлы
```
