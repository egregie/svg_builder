# ТЕХНИЧЕСКОЕ ЗАДАНИЕ v3.1: МОНОХРОМНЫЙ СТАНДАРТ ВЫВОДА + SKETCH-ПАЙПЛАЙН

**Версия:** 3.1 (надстройка над v3.0 HiFi Deterministic Vectorizer)
**Источник:** CHANGE REQUEST — SVG Output Standardization + Human Photo Sketch Pipeline
**Принцип:** Бесплатно, локально, детерминированно. Любой вход → валидный ч/б вектор на прозрачном фоне.

## 0. Аудит change request: что корректно, что требует правки `[АНАЛИЗ]`

### Корректно и принимается без изменений
- Разделение «фото человека → скетч» и «графика → стандартная реконструкция + ч/б нормализация» — архитектурно верно. Фото объективно не векторизуются заливками (подтверждено на `lisa_14`: SSIM_orig 0.48, цветовой сдвиг).
- Финальная валидация RULE 1–5 (нет подложки, только чёрный, нет растра/градиентов, прозрачный фон, полностью вектор) — корректный набор инвариантов выпуска.
- Рекомендация о 7-классовой таксономии вместо бинарной — принимается полностью.
- Рекомендация «aspect-ratio важнее фиксированного canvas» и «детализация важнее размера» — принимается, отражено в полях паспорта.

### Требует правки / уточнения (исправлено в этом ТЗ)
1. **`[КОНФЛИКТ C-03]` «Только чёрный» против Zero Black Policy.** Текущий проект (v2.x/v3.0) запрещает `#000`/`#000000` и маппит чёрный на `--dark #2C3440`; QA A05 блокирует pure-black. Change request требует ровно обратного: только `#000000`.
   **`[РЕШЕНИЕ]`** Для **финального рендера** Zero Black Policy **отменяется** и заменяется на Monochrome-Black Standard (только `#000000`, прозрачный фон). `design-tokens.json` сохраняется как справочник, но финальный нормализатор схлопывает все цвета в чёрный. QA-логика forbidden-colors **инвертируется**: теперь запрещён любой не-чёрный цвет в готовом SVG.
2. **Папка `render_output`.** В архитектуре проекта релизная папка — `05_output_svg/` (с `staging/` и `quarantine/`). `[РЕШЕНИЕ]` `render_output` ≡ `05_output_svg/`. Новая папка не создаётся; маппинг зафиксирован, чтобы не плодить параллельные пути.
3. **Бинарная классификация недостаточна** (признано и автором CR). Вводим 7 классов (раздел 2).
4. **«Только линии» для скетча vs «stroke paths».** VTracer-binary выдаёт **заливные контуры** (filled paths), а не центровые штрихи. Для ч/б скетча это эквивалентно по виду (тонкие чёрные формы линий), полностью вектор, без растра. `[РЕШЕНИЕ]` скетч = заливные чёрные пути от бинаризованной линейной карты XDoG; требование «vector curves, без растра, только чёрный» соблюдается. Центровые штрихи (single-stroke) — вне объёма (требуют скелетонизации; запас на будущее).
5. **Уровень детализации `vector_detail_level`** (рекомендация автора CR) — принимается как первичный управляющий параметр (важнее размера canvas), маппится на параметры VTracer и пороги XDoG.

## 1. Этап классификации (новый агент A07 `classify.py`)

Выполняется **до** A02, на этапе A01 (`deconstruct.py` вызывает классификатор и кладёт результат в raw-JSON).

### 1.1 Таксономия (7 классов)
`HUMAN_PHOTO`, `OBJECT_PHOTO`, `LOGO`, `ICON`, `ILLUSTRATION`, `PACKAGE_DESIGN`, `TECHNICAL_GRAPHIC`.

### 1.2 Сигналы (бесплатно, локально)
- **Лица/люди:** OpenCV Haar-каскады (`haarcascade_frontalface_default`, `profileface`, `fullbody`, `upperbody`) — оффлайн, в комплекте cv2. Найдено лицо/фигура → кандидат `HUMAN_PHOTO`.
- **Тональность (фото vs плоская графика):** число уникальных цветов (после округления), наличие градиента (blur-diff), локальная дисперсия/шум, доля плавных переходов. Высокая тональность → фото/иллюстрация; низкая + резкие края → логотип/иконка/схема.
- **Геометрия:** соотношение сторон (узкое/широкое → LOGO/TECHNICAL), квадрат + малый размер + alpha → ICON, наличие alpha-канала.

### 1.3 Детерминированное дерево решений (псевдокод)
```
if faces_or_bodies_detected:            HUMAN_PHOTO
elif is_tonal (много цветов + градиент + шум):
        if aspect близко к квадрату и есть один доминирующий объект: OBJECT_PHOTO
        else:                            OBJECT_PHOTO            # тональное фото
elif few_colors and sharp_edges:
        if square and has_alpha and small: ICON
        elif aspect широкий/узкий (>=2.2:1): LOGO
        elif very_wide (>=3:1) and line-like: TECHNICAL_GRAPHIC
        else:                            LOGO
else:                                    ILLUSTRATION           # флэт-арт средней пестроты
```
Неоднозначные случаи → `ILLUSTRATION` (безопасный дефолт) + запись в `routing_conflicts.jsonl`.
**Ручной override:** если в исходном raw-JSON/паспорте задан `input_type` вручную — он приоритетнее автоклассификации.

### 1.4 Маппинг класс → режим рендера и детализация
| Класс | render_mode | vector_detail_level |
|-------|-------------|----------------------|
| HUMAN_PHOTO | SKETCH_VECTOR | HIGH |
| OBJECT_PHOTO | SKETCH_VECTOR | HIGH |
| ILLUSTRATION | SKETCH_VECTOR если тональная, иначе STANDARD_VECTOR | HIGH |
| LOGO | STANDARD_VECTOR | ULTRA |
| ICON | STANDARD_VECTOR | ULTRA |
| PACKAGE_DESIGN | STANDARD_VECTOR (тональная упаковка-фото → SKETCH_VECTOR) | ULTRA |
| TECHNICAL_GRAPHIC | STANDARD_VECTOR | ULTRA |

Обоснование: для логотипов/иконок/схем потеря кривой критична → ULTRA + заливка. Для фото/тональных допустимо упрощение контуров → HIGH + скетч.

## 2. Два движка рендера (оба → только чёрный, прозрачный фон)

### 2.1 STANDARD_VECTOR — монохромная заливка (надстройка над `hifi_vectorize.py`)
- Квантование/сегментация фон↔передний план (фон = доминанта рамки).
- Объединённая бинарная маска переднего плана трассируется VTracer-binary как **чёрная заливка с дырками** (even-odd): внутренние области фонового цвета остаются прозрачными (сохраняет вырезы логотипа).
- **Нет** background `<rect>`. Фон прозрачный. Все `fill="#000000"`.
- Перцептивный QA-цикл сохраняется: эталон = чёрное-на-белом (fg/bg), SSIM, автоподбор параметров по `vector_detail_level`.
- Реактивный даунскейл при overflow VTracer (из v3.0) сохраняется.

### 2.2 SKETCH_VECTOR — линейный скетч (новый `sketch_vectorize.py`)
- Grayscale + bilateral-денойз (убрать шум кожи/JPEG, сохранить структуру).
- **XDoG** (eXtended Difference of Gaussians) → чистые «карандашные» линии (не комикс/мультфильм). Подтверждено на `lisa_14`: узнаваемый портрет, волосы/глаза/нос/губы/одежда.
- Бинаризация → морфологическая чистка спеклов → VTracer-binary → чёрные пути.
- **Нет** подложки, прозрачный фон, только `#000000`.
- Пороги XDoG/чистки управляются `vector_detail_level`.
- Перцептивный QA: SSIM против бинаризованной линейной карты (структурное сходство линий).

### 2.3 Уровни детализации (общая шкала)
| Уровень | filter_speckle | corner_threshold | length_threshold | XDoG sigma/φ |
|---------|----------------|------------------|------------------|--------------|
| ULTRA | 2 | 30 | 2.0 | — |
| HIGH | 3 | 40 | 3.0 | sigma 1.0, φ 12 |
| MEDIUM | 6 | 60 | 4.0 | sigma 1.3, φ 9 |
| LOW | 10 | 80 | 6.0 | sigma 1.6, φ 7 |

## 3. Размеры / aspect ratio
- viewBox сохраняет **исходное соотношение сторон** (никакого сплющивания в квадрат) — пайплайн v3.0 уже использует исходные w×h как viewBox, требование уже соблюдается.
- В паспорт добавляется `target_canvas` (база 1024 по длинной стороне, пропорции сохранены) и `aspect_ratio` — справочно для потребителей SVG. Фактический viewBox остаётся в исходных координатах (SVG масштабируем).
- `preserve_aspect_ratio: true` для всех классов.

## 4. Изменения схемы паспорта (`passport_schema_v1.json`)
Добавляются свойства (необязательные — обратная совместимость со старыми паспортами):
```jsonc
"input_type":  "HUMAN_PHOTO|OBJECT_PHOTO|LOGO|ICON|ILLUSTRATION|PACKAGE_DESIGN|TECHNICAL_GRAPHIC",
"render_mode": "SKETCH_VECTOR|STANDARD_VECTOR",
"vector_detail_level": "LOW|MEDIUM|HIGH|ULTRA",
"source_width": int, "source_height": int,
"aspect_ratio": "W:H",

"preserve_aspect_ratio": bool
```
`color_token` в слоях делается **необязательным** (для монохрома цвет не нужен); pattern сохраняется для legacy.

## 5. Финальная валидация выпуска (QA-гейт A05, переписан)
Перед записью в `05_output_svg/` (≡ render_output):
- **RULE 1.** Нет фоновых прямоугольников во всю канву / нет background-слоёв.
- **RULE 2.** Только `#000000`/`black`. Любой иной цвет → автоконверсия в `#000000` (нормализатор), затем повторная проверка.
- **RULE 3.** Нет `linearGradient`/`radialGradient`/`filter`/`<image>`/base64-растра.
- **RULE 4.** Фон прозрачный (нет непрозрачной заливки канвы).
- **RULE 5.** Полностью вектор (только path/контурные примитивы).
Нарушение, неустранимое автоконверсией → `quarantine/` + `qa_failures.jsonl`. Перцептивный порог SSIM остаётся (ниже порога → quarantine).

## 6. Интеграция в архитектуру проекта (поток агентов)
```
input/  → A01 deconstruct.py
              ├─ A07 classify.py (новый): input_type, render_mode, detail, aspect

              ├─ STANDARD_VECTOR → hifi_vectorize (monochrome=True)
              └─ SKETCH_VECTOR   → sketch_vectorize (новый)

```
Не ломаем: deconstruct/validate сохраняют прежние поля; legacy-флаг `--legacy` в compile_svg остаётся. preflight.py обновляется на монохромный стандарт.

## 8a. Результаты внедрения `[ФАКТ 2026-06-13]`
Прогон end-to-end на 19 объектах (классификация → паспорт → монохром-рендер).
**16/19 released, 100% соответствуют стандарту** (только `#000000`, прозрачный фон,
без растра/градиентов/подложки — проверено `validate_monochrome`). 3 в карантине
(перцептивный гейт): bambi (мультфильм-силуэт 0.92), kover (ковёр-текстура 0.68),
portal_13 (плотная панель 0.71) — корректно отсеяны, не выпущены как «успех».

Подтверждено визуально:
- `lisa_14` (HUMAN_PHOTO→SKETCH): узнаваемый карандашный скетч, чёрные линии.
- `art_01` (OBJECT_PHOTO→SKETCH): контур фигуры/черепов/луны.
- логотипы/иконки (masson, ym_proskin, how_19 розарий, portal_12): чёткая чёрная
  вектор-версия с сохранением вырезов, прозрачный фон.

Дефекты, найденные и устранённые в ходе внедрения:
- **D-06 (Haar false-positive):** плоский лого `ym_proskin_003` детектился как лицо →
  HUMAN_PHOTO. Фикс: класс HUMAN_PHOTO не присваивается «плоской графике»
  (≤80 цветов и flat_frac≥0.5), даже если каскад сработал.
- **D-07 (инверсия на градиентном фоне):** виньетка-фон (`portal_12`) делилась на
  несколько кластеров; одиночный border-кластер как фон → светлый центр заливался
  чёрным. Фикс: фон = транзитивное single-linkage объединение кластеров (шаг ≤40 RGB)
  от border-семени → вся градиентная цепочка схлопывается в прозрачный фон.
- **D-08 (тонкая рамка):** `pick_background_cluster` теперь берёт крупнейший по
  площади border-кластер (толстая полоса-band 3%), устойчив к декоративным рамкам.

## 9. Открытые ограничения (зафиксированы, не блокируют)
- Классификатор эвристический (без ML) — возможны ошибки на пограничных кейсах; смягчается ручным override в паспорте.
- Скетч даёт заливные контуры, не одно-штриховые центровые линии (single-stroke — запас на будущее, требует скелетонизации).
- Тональные иллюстрации/упаковки-фото — компромисс между скетчем и заливкой; выбор по флагу тональности.
