**Тип:** миграция и правила именования (НЕ качество рендера).
**Надстройка над:** TZ v3.1 (монохром-стандарт) + v3.2 (детализация sketch).
**Принцип:** полная детерминированная пересборка от исходных растров.

---

## 0. Маппинг к архитектуре проекта `[РЕШЕНИЕ]`
- `render_output/` ≡ `05_output_svg/` (релизная папка проекта; зафиксировано с v3.1).
- Внутренний ID-механизм `COMP-NNN` (knowledge graph) **сохраняется** — меняется
  только **имя выходного файла**. Связь ID↔файл пишется в паспорт.

## 1. Полная очистка старых результатов
Перед пересборкой удаляются ВСЕ ранее сгенерированные SVG:
- `05_output_svg/*.svg` (корень, релизы),
- `05_output_svg/staging/*.svg`,
- `05_output_svg/quarantine/*.svg`.
НЕ удаляются: исходные растры (`input/`, `01_input_raster/`), паспорта
(`04_passports/`), knowledge graph (`03_knowledge_graph/`), логи, служебные файлы.

## 2. Полная регенерация
Для каждого исходного изображения заново: классификация (A07) → паспорт (A02) →
обработка новым pipeline (A05) → новый SVG. Запрещено: использовать старые SVG как
источник, конвертировать старые SVG, частичная миграция. Только пересборка от растра.

## 3. Стандарты генерации (из v3.1/v3.2)
- HUMAN_PHOTO → SKETCH_VECTOR, HIGH, черты лица/причёска/одежда сохраняются.
- Все классы → прозрачный фон, только `#000000`, только вектор.

## 4. Стандарт именования выходного файла
```
output = "svg_" + <имя_исходника_без_расширения> + ".svg"
```
Примеры: `lisa_14.jpg` → `svg_lisa_14.svg`; `product_box_v2.png` → `svg_product_box_v2.svg`.

## 5. Уникальность имён (коллизии)
Если `svg_<stem>.svg` уже занято в этом прогоне — суффикс `_NN`:
`svg_logo.svg`, `svg_logo_01.svg`, `svg_logo_02.svg`.

## 6. Порядок исходников `[Preserve source file ordering = TRUE]`
Обработка в **натуральном** порядке имён исходников (01,02,…,10, а не 1,10,2),
чтобы `svg_01.svg, svg_02.svg, svg_03.svg` соответствовали порядку входа —
упрощает сравнение старых/новых результатов и присвоение суффиксов коллизий.

## 7. Обновление metadata паспорта
В `03_knowledge_graph/COMP-NNN.json` добавляются:
```json
{ "source_filename": "lisa_14.jpg", "output_filename": "svg_lisa_14.svg" }
```

## 8. Валидация после генерации (per-file)
1. Имя соответствует `^svg_.+\.svg$`.
2. SVG создан новым pipeline (агент A08 в `agent_trace.jsonl`).
3. Нет растровых данных (`<image>`/base64).
4. Прозрачный фон (нет фоновой подложки).
5. Только `#000000` (и `none`).
6. Валидный XML (открывается парсером).
Пункты 3–6 = существующий `validate_monochrome` (RULE 1–5); пункт 1 — проверка имени.

## 9. Ожидаемый результат
`input/lisa_14.jpg` → `05_output_svg/svg_lisa_14.svg`, собран заново, без данных
старых рендеров. Старые `COMP-NNN.svg` отсутствуют.
